  🏗️ ARCHITECTURE
================================================================================

    Device 0 (Client)              Device 1 (Server)
  ┌─────────────────────┐        ┌─────────────────────┐
  │ • Has data          │        │ • Waits for client  │

  │ • Orchestrates      │        │ • LM Head           │
  │   training          │        │ • Computes loss     │
  │                     │  ←→    │                     │
  │ Send: hidden_states │ WebSocket │ Send: loss       │
  │ Recv: gradients     │        │ Recv: hidden_states │
  │                     │        │                     │
  └─────────────────────┘        └─────────────────────┘

================================================================================
  ⚙️ CONFIGURATION EXAMPLES
================================================================================

Small GPU (< 4GB):
  --train_batch_size 1 --seq_len 64 --grad_acc 8

Medium GPU (8GB):
  --train_batch_size 2 --seq_len 256 --grad_acc 2

Large GPU (16GB+):
  --train_batch_size 4 --seq_len 512 --grad_acc 1

Two GPUs:
  Server: --server_device cuda:1
  Client: --client_device cuda:0

Remote Training:
  Server: --server_host 0.0.0.0
  Client: --server_host <server_ip>

================================================================================
  🐛 TROUBLESHOOTING
================================================================================

Problem                     Solution
──────────────────────────────────────────────────────────────────
Connection refused          → Start server (device_id=1) first
CUDA out of memory          → Reduce batch_size and seq_len
Port already in use         → Use --server_port 8766
Missing data files          → Provide --train_data path
Training too slow           → Use same machine or faster network

See QUICKSTART.md and DISTRIBUTED_TRAINING.md for more help.
